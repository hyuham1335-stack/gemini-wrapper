## 1. 제품 개요

Gemini Wrapper는 Google Gemini API를 감싼 **구독형 SaaS 채팅 서비스**입니다.
사용자는 Google 계정으로 로그인해 대시보드에서 Gemini와 실시간 스트리밍 대화를 하고,
대화 내역은 서버에서 암호화되어 보관됩니다. 사용량은 월 단위로 플랜별 한도가 적용되며,
유료 전환·플랜 변경·해지는 Polar 결제로 처리됩니다.

**한 줄 정의**: "로그인만 하면 바로 쓰는, 대화가 안전하게 남는 유료 Gemini 채팅."

## 2. 해결하려는 문제

| 문제 | 설명 |
| --- | --- |
| API 키 진입 장벽 | 일반 사용자는 Google AI Studio에서 키를 발급받고 요금을 관리하는 과정 자체가 부담. |
| 대화 휘발 | 순수 API 호출은 대화 기록이 남지 않아 이어서 쓰기 어려움. |
| 기록 프라이버시 | 대화 내용이 평문으로 DB에 쌓이는 서비스에 민감한 내용을 넣기 어려움. |
| 비용 예측 불가 | 종량제는 월 비용을 예측하기 어려움 — 정액 구독과 명확한 한도가 필요. |

## 3. 타깃 사용자

- **주 사용자**: Gemini를 가볍게 쓰고 싶지만 API 키 발급·과금 관리를 하고 싶지 않은 한국어권 개인 사용자.
- **부 사용자**: 대화 기록이 서버에 암호화 저장되기를 원하는 프라이버시 민감 사용자.
- **비대상**: 팀 협업/조직 계정, 자체 API 키 반입(BYOK), 대량 배치 호출이 필요한 사용자.

## 4. 제품 원칙

1. **로그인 후 3클릭 안에 첫 응답** — 온보딩 설정 단계를 만들지 않는다.
2. **한도는 항상 정확하게** — 동시 요청으로도 한도를 넘길 수 없고, 실패한 요청은 한도를 소모하지 않는다.
3. **저장되는 사용자 콘텐츠는 암호화한다** — 대화 제목·본문·프로필은 평문으로 두지 않는다.
4. **UI 문구는 한국어** — 사용자에게 노출되는 모든 메시지는 한국어로 통일한다.

## 5. 핵심 사용자 시나리오

1. **첫 사용**: 랜딩 → "Google로 시작하기" → OAuth 동의 → `/dashboard` 진입 → 새 대화에 질문 입력 →
   응답이 토큰 단위로 스트리밍되어 표시됨.
2. **이어서 쓰기**: 좌측 사이드바에서 이전 대화 선택 → 이전 메시지가 복호화되어 로드 → 문맥을 이어 질문.
3. **한도 도달**: Free 사용자가 11번째 메시지를 보내면 전송이 차단되고 페이월 모달 → `/pricing`으로 이동.
4. **업그레이드**: `/pricing`에서 Pro 선택 → Polar 체크아웃 → 결제 완료 → 웹훅이 플랜을 동기화 →
   `/pricing/success` 안내 → 대시보드에서 상향된 한도로 사용.
5. **구독 관리**: `/billing`에서 현재 플랜·이번 달 사용량 확인 → 플랜 변경 / 해지 예약 / 해지 취소 /
   Polar 고객 포탈(결제수단·인보이스)로 이동.
6. **기록 찾기**: 대시보드 검색에서 키워드 입력 → 전체 대화의 메시지 본문에서 일치 항목을 찾아 해당 대화로 이동.

## 6. 기능 요구사항

### 6.1 인증 (Auth)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| A-01 | Google OAuth(Supabase Auth)로만 로그인한다. 이메일/비밀번호 가입은 제공하지 않는다. | 구현됨 |
| A-02 | `/dashboard`, `/billing`은 비로그인 시 `/login?redirectedFrom=...`으로 리다이렉트한다. | 구현됨 |
| A-03 | 이미 로그인한 사용자가 `/login`에 접근하면 `/dashboard`로 보낸다. | 구현됨 |
| A-04 | 로그인 콜백 시 프로필(이메일·이름)을 암호화하여 저장/갱신한다. | 구현됨 |

### 6.2 채팅 (Chat)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| C-01 | 사용자는 새 대화를 생성하고 메시지를 보낼 수 있다. | 구현됨 |
| C-02 | Gemini 응답은 스트리밍으로 즉시 화면에 표시된다(완료를 기다리지 않음). | 구현됨 |
| C-03 | 이전 대화 내역을 문맥으로 함께 전달해 대화가 이어진다. | 구현됨 |
| C-04 | 대화의 첫 메시지 앞 24자를 잘라 대화 제목으로 자동 지정한다. | 구현됨 |
| C-05 | 대화 목록 조회·선택·삭제가 가능하다. | 구현됨 |
| C-06 | 응답이 비어 있거나 스트림이 중단되면 어시스턴트 메시지를 저장하지 않는다. | 구현됨 |
| C-07 | 모든 대화 제목과 메시지 본문은 암호화되어 저장된다. | 구현됨 |
| C-08 | 사용자는 자신의 전체 메시지 본문을 키워드로 검색하고, 결과에서 해당 대화로 이동할 수 있다. | 구현됨 |

### 6.3 사용량 및 플랜 (Usage & Plans)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| U-01 | 플랜별 월간 호출 한도: Free 10회 / Pro 100회 / Unlimited 무제한. | 구현됨 |
| U-02 | 구독 행이 없는 신규 사용자는 암묵적으로 Free 플랜으로 취급한다. | 구현됨 |
| U-03 | 한도 초과 시 요청을 429로 거절하고 업그레이드 경로(`/pricing`)를 함께 안내한다. | 구현됨 |
| U-04 | 동시 요청으로 한도를 우회할 수 없어야 한다(원자적 예약). | 구현됨 |
| U-05 | 응답 생성에 실패한 요청은 사용량을 소모하지 않는다(예약 해제). | 구현됨 |
| U-06 | 대시보드/청구 페이지에서 이번 달 사용량과 남은 횟수를 확인할 수 있다. | 구현됨 |
| U-07 | 사용량은 `YYYY-MM` 단위로 집계되며 달이 바뀌면 자동으로 새로 시작한다. | 구현됨 |

### 6.4 결제 및 구독 (Billing)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| B-01 | `/pricing`에서 플랜을 비교하고 유료 플랜 체크아웃을 시작할 수 있다. | 구현됨 |
| B-02 | 이미 활성 구독이 있으면 신규 체크아웃 대신 "플랜 변경"으로 유도한다. | 구현됨 |
| B-03 | 유료 플랜 간 변경(Pro ↔ Unlimited)이 가능하다. | 구현됨 |
| B-04 | 해지는 기간 말 해지 예약이며, 예약 취소(구독 재개)도 가능하다. | 구현됨 |
| B-05 | 해지 예약 상태는 대시보드/청구 페이지에 배너로 안내한다. | 구현됨 |
| B-06 | 결제수단·인보이스 관리는 Polar 고객 포탈로 위임한다. | 구현됨 |
| B-07 | 결제 상태 변화(활성/연체/취소/해지)는 Polar 웹훅으로 동기화한다. | 구현됨 |
| B-08 | 웹훅은 서명 검증에 실패하면 거절하고, 같은 이벤트를 두 번 처리하지 않는다. | 구현됨 |
| B-09 | 결제가 완료되지 않은(`incomplete`) 구독에는 유료 플랜을 부여하지 않는다. | 구현됨 |

## 7. 플랜 정책

| 플랜 | 가격 | 월 한도 | 비고 |
| --- | --- | --- | --- |
| Free | $0 | 10회 | 가입 즉시 기본값, 구독 행 없음 |
| Pro | $9.99/월 | 100회 | Polar 구독 |
| Unlimited | $29.99/월 | 무제한 | Polar 구독 |

- 한도의 단일 진실 공급원은 `lib/polar/plans.ts`의 `PLAN_LIMITS`입니다. 가격/한도 변경 시 이 파일과
  Polar 상품을 함께 수정해야 합니다.
- 구독이 `revoked`되면 플랜은 `free`로 되돌아갑니다(대화 기록은 삭제하지 않음).

## 8. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 보안 | 사용자 콘텐츠(대화 제목/메시지/프로필)는 AES-256-GCM으로 암호화 저장. 모든 테이블에 RLS 적용. |
| 보안 | service-role 키는 서버 전용 경로(웹훅·usage RPC·프로필 동기화)에서만 사용하고 클라이언트에 노출하지 않음. |
| 정확성 | 사용량 카운트는 동시 요청 환경에서도 한도를 초과하지 않아야 함. |
| 응답성 | 첫 토큰이 도착하는 즉시 화면에 표시(전체 응답 대기 금지). |
| 국제화 | 사용자 노출 문자열은 한국어, 날짜 포맷은 `ko-KR`. |
| 운영 | 배포는 Vercel + Supabase 관리형 인프라. 별도 백엔드 서버를 두지 않음. |

## 9. 성공 지표 (제안)

- 로그인 → 첫 메시지 전송 전환율
- Free 한도 도달 사용자 중 유료 전환율
- 유료 구독 월 이탈률(해지 예약 발생률 포함)
- 채팅 요청 실패율(5xx / Gemini 오류 비율)

## 10. 범위 외 (Out of Scope)

- 팀/조직 계정, 멤버 초대, 역할 권한
- 사용자 본인 API 키 반입(BYOK)
- 파일 업로드·이미지 입력·툴 호출 등 멀티모달 기능
- 대화 공유 링크, 내보내기(export)
- 관리자 백오피스, 사용자별 수동 한도 조정
- 자동화된 테스트 스위트 (현재 저장소에 구성되어 있지 않음)

## 11. 알려진 제약 및 향후 과제

| 항목 | 현황 | 방향 |
| --- | --- | --- |
| 검색 성능 | 암호화 컬럼은 SQL에서 매칭할 수 없어 서버에서 전량 복호화 후 필터, 상위 50건 제한. | 대화 수 증가 시 페이지네이션 또는 검색 전용 인덱스 설계 필요. |
| 사용량 단위 | 토큰이 아니라 "요청 횟수" 기준. | 장문 응답 비용 편차가 커지면 토큰 기준 과금 검토. |
| 스트림 중단 | 사용자가 중간에 이탈하면 어시스턴트 메시지가 저장되지 않고 사용량이 반환됨. | 부분 응답 저장 여부 정책 결정 필요. |
| 테스트 | 자동화 테스트 없음, lint + build로만 검증. | 최소한 사용량 예약/해제와 웹훅 idempotency에 대한 테스트 도입 검토. |
| 모델 선택 | `GEMINI_MODEL` 단일 상수로 고정. | 플랜별 모델 차등 제공 검토. |
